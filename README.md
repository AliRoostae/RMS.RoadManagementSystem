# سامانه مدیریت راه و حوادث رانندگی

این پروژه برای سازمان‌ها و تیم‌هایی ساخته شده که باید اطلاعات راه‌ها، محدوده‌های جغرافیایی و حوادث رانندگی را یک‌جا ثبت، پیگیری و تحلیل کنند.

با این سامانه می‌شود:

- راه‌ها و محدوده‌های جغرافیایی را روی نقشه ثبت و مدیریت کرد.
- جزئیات حادثه را ثبت کرد؛ مثل زمان، موقعیت، وضعیت هوا، وضعیت راه، روشنایی، علائم و علت حادثه.
- خودروهای درگیر، راننده‌ها، سرنشین‌ها و افراد خارج از خودرو را به حادثه وصل کرد.
- عکس‌های مربوط به حادثه را نگه‌داری و مدیریت کرد.
- اطلاعات کاربران و سطح دسترسی آن‌ها را کنترل کرد.
- از داده‌های ثبت‌شده گزارش و آمار گرفت و روند حوادث را دید.

### این سامانه به درد چه کسانی می‌خورد؟

این پروژه بیشتر برای سازمان‌های راهداری، شهرداری‌ها، پلیس راه، شرکت‌های حمل‌ونقل، واحدهای ایمنی جاده و تیم‌های تحلیل حوادث کاربرد دارد؛ هر جایی که ثبت منظم حادثه و تصمیم‌گیری بر اساس داده مهم باشد.

### کاربر معمولاً با چه چیزی روبه‌رو می‌شود؟

کاربر از طریق رابط وب وارد سامانه می‌شود. بعد از ورود، بر اساس دسترسی خودش می‌تواند راه‌ها، حوادث، خودروها، افراد، تصاویر، کاربران و گزارش‌ها را ببیند یا مدیریت کند. فرم‌ها ورودی‌ها را کنترل می‌کنند .

### نمای کلی فنی برای توسعه

پروژه به چند لایه تقسیم شده تا هر بخش کار خودش را انجام بدهد و تغییر دادن یک قسمت، بقیهٔ پروژه را بی‌دلیل به هم نریزد:

- [Shared](RMS.Shared/): قراردادهایی که API و Client هر دو می‌فهمند.
- [Domain](RMS.Domain/): موجودیت‌ها و قواعد اصلی کسب‌وکار.
- [Application](RMS.Application/): سناریوهای کاری و سرویس‌های برنامه.
- [Infrastructure](RMS.Infrastructure/): دیتابیس، EF Core، فایل‌ها و سرویس‌های فنی.
- [Api](RMS.Api/): درگاه HTTP، احراز هویت، دسترسی و مدیریت خطا.
- [Client](RMS.Client/): رابط کاربری Blazor و ارتباط آن با API.

مسیر سادهٔ یک درخواست این شکلی است:

کاربر در Client کاری انجام می‌دهد، Client یک درخواست به Api می‌فرستد، Api آن را به Application می‌دهد، Application قوانین را اجرا می‌کند و از طریق قراردادهای Domain به Infrastructure می‌رسد. نتیجه دوباره از همین مسیر به کاربر برمی‌گردد.

## چند نکتهٔ مهم

- اطلاعات مکانی راه‌ها و حوادث با مختصات جغرافیایی کار می‌کنند و برای نمایش روی نقشه آماده‌اند.
- دسترسی‌ها فقط یک ورود ساده نیستند؛ نقش کاربر و مجوز هر بخش هم بررسی می‌شود.
- عکس‌ها جدا از اطلاعات متنی حادثه مدیریت می‌شوند تا ثبت و حذف آن‌ها کنترل‌شده باشد.
- قراردادهای مشترک در Shared قرار گرفته‌اند تا شکل داده بین Client و Api یکی بماند.
- ریت لیمیت بر حسب آیپی و برای لاگین اعمال شده با قفل یک دقیقه 
- نام کاربری و پسورد اولیه را  حتما تغییر دهید در فایل DatabaseInitialization.cs  هارد کد کردم برای ماگریشن اولیه


## چرا این پروژه را ایجاد کردم ؟

با توجه به تجربیاتی که در زمینه جادهها کشور در طول سالها برنامه نویسی مرتبط با  سامانه های پلاک خوان و اخذ عوارض نیمه  مکانیزه  داشتم  همیشه جای خالی چنین نرم افزاری را به امید کمک هرچند کوچک در راستای کاهش حوادث حس می کردم  .  تصمیم گرفتم این نرم افزار را به صورت سورس باز  تا حد توان  انجام دهم و امیدوارم  در آینده آن را گسترش دهم .

### آنچه در آینده  به آن فکر میکنم 
-  ارتباط با سامانه دریافت وضعیت آب و هوایی  با توجه به زمان حادثه
- ایجاد تقویم تعطیلات و افزودن تعطیلات آتی به صورت یک ماژول مستقل 
- ایجاد یک سرویس آنالیز داده بر اساس تعطیلات و شرایط آب و هوایی و عوارض جاده طوری که  داده های فوق برای  ایجاد یک سامانه پیش بینی نقاط پر خطر در طول مسیر و پیش بینی وقوع حوادث که نیازمند موارد ذیل خواهد بود
	- ایجاد کنترلر استاندارد برای سامانه های شمارش ترافیک بر حسب مختصات 
	- تولید زیر سامانه ثبت تابلوهای اطلاع رسانی و حفاظ ها در طول مسیر به همراه مختصات 
	- تولید زیر سامانه ثبت خرابی و عوارض مسیر  
- استفاده از نقشه لوکال وآفلاین
- خروجی داکر برای راه اندازی سریع
